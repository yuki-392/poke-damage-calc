# ChampionCalc 画面設計書 v0.5

- 更新日：2026-10-23
- 対象：Pokémon Champions 専用ダメージ計算 Web アプリ（PC・スマートフォン）
- 前提資料：要求定義 v0.2・要件定義 v0.3・画面設計 v0.4
- 状態：UI プロトタイプ。表示中のダメージ・TOP50順位は架空のサンプル、ゲーム内計算エンジン・API・認証・共有機能は未接続。

## 1. 今回の設計意図

通常計算は「攻撃側／防御側をその場で編集し、結果を見る」。TOP50 は「多くのポケモンの結果を一目で比較し、必要な個体のみ『詳細』で調整する」。共通の詳細条件 UI と検索可能な入力コントロールを採用する。

## 2. 画面構成

| ID | 画面 | 主要操作 |
|---|---|---|
| SCR-01 | 通常ダメージ計算 | 攻防指定、攻守交換、最大4技、条件、ダメージ結果 |
| SCR-02 | TOP50まとめ計算 | 攻撃側設定、50匹×最大4技、検索・絞り込み・並び替え、各セルから詳細 |
| SCR-03 | TOP50詳細（ドロワー／ボトムシート） | 技変更、型編集、ダメージ範囲・割合・確定数、詳細限定の戦闘条件、通常計算への引き継ぎ |
| SCR-04 | 保存した計算 | 保存済み条件一覧（モックは仮保存のみ） |
| SCR-05 | 保存・共有・アカウント | 実装に向けた導線のみ |

## 3. 検索選択コンポーネント

ポケモン名、技、特性、持ち物に共通のコンボボックスを使う。

- 入力開始・フォーカス時：入力文字に応じて候補を表示。
- 右端の `▾` ボタン：入力値に関係なくすべての通常候補を表示。
- 候補の二段目：効果、タイプ／分類／威力、説明を表示。ポケモンはタイプ表示。
- 技候補：通常は対象ポケモンの習得技だけを表示する。名前を入力した場合は、習得外の既知の技も指定できる。デモではデータ登録外の技も文字列として表示するが、本番では技データと照合する。
- 技効果：追加効果の発生率を `30%でひるみ`、`10%でまひ` などの形式で明示する。確実な変化は `100%` と表示。技範囲の説明は `範囲技` と短く表記する。
- 特性：そのポケモンが持つ特性の候補**だけ**を使用可能とする。候補外の自由入力は認めない。選択状態の下に効果を表示。
- 持ち物：候補から選択でき、自由入力も可能。登録済みの持ち物は効果を表示し、未登録の入力値には `効果データ未登録` と明示する。
- UI モックの候補・習得技・効果は例示データ。本番マスターデータに差し替える。

## 4. 能力ポイント・実数値の双方向編集

### 4.1 対象項目

- 攻撃側：物理なら攻撃、特殊なら特攻のみ。
- 防御側：HP＋物理なら防御、特殊なら特防のみ。
- 性格欄：表示中の該当能力について `0.9 / 1.0 / 1.1` 倍を選ぶ。
- 能力ポイント：1能力 0〜32、合計 66 以内。
- 能力ランク：−6〜＋6。
- 数値入力欄には `−` と `＋` のボタンがあり、押すたびに 1 ずつ変わる。

### 4.2 実数値式（レベル50固定）

- HP = 種族値 + 能力ポイント + 75
- HP以外 = floor((種族値 + 能力ポイント + 20) × 性格倍率)

### 4.3 変更時の処理

**能力ポイント → 実数値**：ポイントを変更した瞬間に実数値を再計算する。性格倍率変更時にも再計算する。

**実数値 → 能力ポイント**：指定された実数値と一致する能力ポイントを 0〜32 の範囲から探索し、残りのポイント予算を満たすものを選ぶ。同じ実数値になる候補が複数ある場合、現設定に近いポイントを優先する。

**成立しない実数値**：実数値入力は残し、対応する能力ポイントを `?` とする。入力エラーの説明を出す。本番の計算エンジンはこの状態を未確定入力として扱い、信頼できるダメージ結果を出さない。

HPを編集した場合、現在HPは最大HPを超えないようにする。非表示の能力ポイントは内部設定として保持し、合計値の検証対象とする。

### 4.4 攻守の入れ替え

通常計算画面の `⇄ 攻守を入れ替え` ボタンから、両ポケモンの型を交換する。新しい攻撃側の4技は、そのポケモンの習得技候補で初期化する。天候・壁等の共通条件は維持する。

## 5. TOP50の一覧

### 5.1 PC

- ポケモン名・順位と、4つの技それぞれの残HPバー・確定数のみを主表示する。
- バーにはダメージ割合 `52〜65%` を小さく添える（見たい数字を一覧上で失わないため）。
- 型のラベル、実数ダメージ、条件、説明などは一覧に並べず詳細画面に集約する。
- ポケモン名または技セルを選ぶと詳細を開く。
- 既存の確定数フィルターにある `3発以上` はそのまま保持する。**結果の確定数表示**には `確定3発`、`乱数5発(31.2%)` のように具体的な回数を出す。

### 5.2 スマートフォン

- 初期表示では攻撃側の入力と戦闘条件を折りたたむ。
- ヘッダー直下に、対象の攻撃側ポケモンと選択技数を示す `設定を開く` 行を配置する。
- TOP50の検索・フィルター・並び替えも初期状態では折りたたむ。
- 4技を切り替えるタブはランキング領域上部に固定し、長い一覧のスクロール中も操作できる。
- 1行に「順位＋ポケモン名」「残HPバー＋割合」「具体的な確定数」を並べる。
- 行全体のタップで詳細を開く。型編集用の専用ボタンは設けない。

### 5.3 HPバー

- 左側の現在HP領域が残り、右端から失われたHPを表す（ゲームに近い表現）。
- 最大ダメージ時の残HPに応じて緑・黄・赤・濃赤を使う。
- 51〜100%：緑、21〜50%：黄、1〜20%：赤、0%：濃赤。
- 乱数による最小・最大残HPの幅は薄い領域として重ねる。
- 同じ行に「与ダメージ ○〜○%」の数字を保持する。
- これらの色のしきい値は本番デザイン実装時にゲーム表現と再照合する。

## 6. 詳細画面（最重要）

### 6.1 一覧の行を選んだ直後

詳細に以下を表示する。

1. 対象ポケモン名、育成型の種別（実測代表型／推定代表型／カスタム）。
2. 現在対象の技（検索・候補メニューで変更可能）。
3. ダメージ実数範囲とHP割合。
4. 攻撃後の残HPバーと `確定n発` または `乱数n発(XX.X%)`。
5. 防御側の型：HP、HP能力ポイント、防御または特防、能力ポイント、性格倍率、能力ランク、特性、持ち物、現在HP。
6. 詳細内の戦闘条件：天候、フィールド、各種チェックボックス。
7. `閉じる`、`通常計算へ` の2操作。

**削除した表示**：`16通りの乱数` 一覧、独立した `撃破判定` セクション、`最短撃破` サブ表示。全体は `詳細` という名称に統一。

### 6.2 詳細内の編集と反映範囲

**ポケモンの型の編集**：対象ポケモンのTOP50カスタム型として保持する。閉じた後も、そのランキング個体の以後の計算に利用される。`代表型に戻す` も可能。

**技の変更**：詳細内だけで比較対象の技を一時的に差し替え、詳細の計算結果を更新する。TOP50一覧の4技そのものは変更しない。閉じたら破棄する。

**戦闘条件の変更**：詳細を開いた際にTOP50の戦闘条件をコピーして、独立した一時状態を作る。変更後の条件は**詳細だけ**の計算に反映し、TOP50一覧の共通条件を変えない。閉じたら破棄する。

**通常計算へ**：詳細内で確定した防御側の型・変更中の技・詳細のローカル戦闘条件・攻撃側の型・バトル形式を通常計算に引き継ぐ。ここでは選択中の技を通常計算の先頭スロットに置き、他の技も残す。

### 6.3 状態の寿命

| 状態 | TOP50詳細を閉じる | 「通常計算へ」遷移 |
|---|---|---|
| TOP50共通条件 | 不変 | 詳細条件で置き換えられる |
| 詳細内の戦闘条件 | 破棄 | 通常計算へ引き継ぎ |
| 詳細内の選択技 | 破棄 | 通常計算の技1へ引き継ぎ |
| 対象ポケモンの型編集 | TOP50の個別設定として保持 | 通常計算の防御側へ引き継ぎ |
| 攻撃側の型 | 不変 | 通常計算の攻撃側へ引き継ぎ |
| シングル・ダブル | 不変 | 同じ形式を引き継ぎ |

## 7. 通常計算画面

- 攻撃側・防御側の両方で能力値の相互連動を使用。
- 技・特性・持ち物・ポケモン名の入力形式はTOP50と共通。
- `⇄ 攻守を入れ替え` を配置。
- 結果は4技、実数ダメージ、与ダメージ割合・残HPバー、確定数、詳細ボタンを表示する。
- `乱数n発` には計算された確率を必ず付ける。`3発以上` の丸め表現を結果には使用しない。
- `最短撃破` 行は設けない。

## 8. モック実装上の制限

- 順位は50件の合成データであり、実際の使用率ランキングではない。
- 数値はデモ用疑似計算。公式ゲーム仕様に基づく与ダメージ計算器ではない。
- KO確率表示は架空のダメージ乱数から作った例である。
- ポケモン・技・特性・持ち物は代表的な候補のみを収録。
- 保存は一時的な画面内デモ。認証・同期・URL共有は未実装。
- 本番では「ありえない実数値」時の計算不可表示とデータ検証をサーバー／エンジン層まで担保する。
