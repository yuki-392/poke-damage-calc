# P0-06 ダメージ計算ルール 正確性監査 v1.0

- 確認日：2026-10-23（日本時間）
- 対象：Pokémon Champions、シングル／ダブル、通常計算／TOP50共通エンジン
- 作業範囲：**設計と文献照合のみ**。コードの本格実装やゲーム本体でのバトル再現は行わない。
- 適用スコープ更新：共有URL・公開スナップショット・その90日保持機能はU-06で初期リリースから除外済み。以後の旧ダメージ設計文書の「共有」は無効。

## 1. 結論と根拠レベル

| テーマ | 現在言えること | 現状 | 出典・根拠レベル |
|---|---|---|---|
| Lv50能力ポイント | HPはB+75+P、非HPはfloor((B+20+P)*補正)。各0-32、合計66 | 設計モデル確定、実機の境界検証待ち | 内部合意／公開二次資料（L1/L2） |
| 基礎ダメージ | Wikiの Lv50 / 威力100 / A182 / D189 → 基礎44、乱数候補37～44 | 参考例でL2相当 | Champions育成考察Wiki（L2） |
| 乱数段階 | 現行資料は85～100の16通りと記述。発売直後の15通り説もある | **現行16を採用候補**、版を固定しL3確認 | Wiki・独立資料（L2） |
| 4096補正と丸め | 数式・補正値は詳細に記述。ただし他資料との丸め位置に食い違い | **P0要照合**。決め打ち禁止 | Wikiとデータポータル（L2間差異） |
| ダブル範囲技 | 2体以上に同時ダメージのとき0.75倍の参考記載あり | 条件モデル妥当、補正位置はL3待ち | Wiki（L2） |
| 壁 | シングルとダブルで倍率が異なる。急所時の扱いも異なる | **単一固定倍率として実装禁止** | Wiki（L2）、実機未確認 |
| 特性・持ち物・変動威力技 | 効果ごとに適用箇所・相互作用が違う | 現行の全マスター監査／実機照合待ち | v1.2 効果レジストリ |

## 2. 文献を突き合わせて見つかった注意点（今回の具体的成果）

### 2.1 異なる補正段階を最後に一括乗算してはならない

- Wikiは「威力補正」「攻撃補正」「防御補正」「ダメージ補正」の4096分率合成と、その後の最終計算順を詳述する。
- 別のデータポータルは段階的な切り捨てを説明する一方、壁・範囲技・やけどを「その他」にまとめて説明する箇所がある。
- **実装ルール**：資料が衝突したときは sourceId と段階・丸め方式・条件を比較表に起こし、*端数が変わる入力*の実測ゴールデンケースを追加する。どちらの資料もゲームの一次仕様書とはみなさない。

### 2.2 急所×壁、範囲技×壁の丸め位置は優先検証

- Wikiの詳細最終式にはダブル範囲技の3072/4096、急所の6144/4096、やけど・壁などの最終補正が別々に配置される。
- そのWikiの補正値一覧には壁「シングル0.5／ダブル約2/3」相当が存在する。現行プロトタイプの`scope=singles/doubles`に対応する分岐を、**exact modulus と抑止条件**まで確認すること。
- **設計上の必須例**：物理壁・特殊壁・オーロラベール、急所あり/なし、単体技/複数命中の組み合わせ。最後に一律0.5倍はしない。

### 2.3 15段階説と16段階説

- 2026年10月現在に確認できるWikiと複数の計算ツールは **85..100の16通り** を採用。
- 一部の独立サイトは、2026年4月23日以前に15通りだったと説明する。これは公式更新履歴との照合を済ませた事実とは扱わない。
- 対応：`ruleVersion`に分布の仕様を持たせ、初期候補は現行16通り。現行Championsと照合できるまでは`verified_in_game`にしない。**各実測打撃は乱数候補集合に含まれるか**という検査が可能だが、観測1回で16段階等確率を実証することはできない。

### 2.4 WikiにChampions未収録の旧作品要素が混在

- Wikiにはテラスタル・Z技・ダイマックス関連の記述がある。**記載されていることはChampionsで使用可能なことの証明にならない**。
- 技・特性・持ち物・フォームはChampionsのバージョン付きマスターで *使用可能性* を確認し、実装方式とは独立の表に登録する。
- ルール未確定の効果を黙って0倍率・等倍扱いしない。

### 2.5 KO確率表示「56.2%」の端数仕様は1件残る

- 16分の9は厳密に56.25%。小数1桁の四捨五入なら **56.3%**、小数1桁の切り捨てなら **56.2%**。
- 先行のユーザー要件サンプルは `乱数1発(56.2%)`、v1.2設計の暫定実装方針は四捨五入で56.3%。**現状は設計間の不整合**。
- 統合設計への推奨：要件例を優先して表示は小数1桁「切り捨て」、内部は既約分数/整数カウントのまま厳密に保持。正式な表示丸め規則はユーザー承認を経て最終決定する。

### 2.6 先行v1.1の23テストはゲーム一致の証拠ではない

- コア計算、タイプ、天候、壁、条件付きの200組呼び出しの**ソフトウェアテスト成功**を示すもの。
- それだけでゲーム本体の補正値、丸め順序、メガ、特殊効果の正しさは担保しない。
- Codexは既存実装を「参考・候補」として扱い、**テストケースにゲーム版・出典・入力・期待値**がないものをL3として引き継いではならない。

## 3. 比較用の独立リファレンスを追加

`@smogon/calc` の公開ソースには `calc/src/mechanics/champions.ts` が存在し、Champions向け計算経路として使える。GitHubリポジトリのライセンスはMIT（著作権表示等の条件あり）。現時点でこれを**採用エンジンへの置き換えとは決定しない**。既存の独立TSコア案と比較して、次の検証に使う候補とする。

1. 参照バージョン（コミットSHAとnpmバージョン）を固定する。
2. Champions専用計算経路を使用し、SV系の計算処理を誤使用しない。
3. 能力ポイント・フォーム／メガ・ルール版を入力へ正しくマッピングする。
4. 参照実装と結果が異なるケースを差分として保存する。
5. **一致してもL2**。ゲーム実機証拠やゲーム内仕様の裏付けなしにL3にはしない。
6. 外部ライブラリを使うかは、実装前の技術判断としてADRに記録する。取り込む場合はライセンス表示・依存管理・性能比較をセットで行う。

## 4. 計算コアの最終入力・出力条件

- **入力**：`ruleVersion`、`masterDataVersion`、`regulationId`、フォームID、全6能力ポイント、能力補正、現在/最大HP、技ID、特性ID、持ち物ID、天候/フィールド、壁/急所/ランク、ダブル実対象数、必要に応じて補助条件。
- **出力**：`ok`/`nonDamaging`/`missingContext`/`unsupported`/`invalid`、16通りまたは固有の重み付き分布、最小～最大ダメージ、現在HPに対するKO確率、根拠/ルール版/適用効果トレース。
- 現在HPと最大HPの差、非表示6能力・未使用性格補正の消失、持ち物未登録、特性の中立確認漏れを検証する。
- **通常計算とTOP50は同一エンジン**。同一正規化入力で全乱数分布、KO確率、トレースがビット単位で等しいこと。
- 先行資料中の共有URL発行API／共有スナップショット／過去TOP50再現は**廃止**。保存は個人用設定のみ。

## 5. 実装時の状態機械

| 状態 | 意味 | 画面と計算の挙動 |
|---|---|---|
| `implemented + game_verified` | 現行版で条件・丸めまで確認済み | 通常の計算結果。証跡IDを保持 |
| `implemented + secondary_only` | 二次資料と単体テストに一致 | **未実機検証**の管理状態。正式な精度合格とは扱わない |
| `missingContext` | 計算可能だが入力不足 | 入力を促す。数値なし |
| `unsupported` | 現行技・効果の計算未対応／未検証で仕様が衝突 | 誤値を出さない。数値なし |
| `invalid` | 技ID/ポイント配分/フォーム等が不正 | 入力エラー。数値なし |
| `audited_neutral` | その文脈で本当に無関係と確認済み | **記録付き**で補正なし。未知を中立にしない |

`game_verified`には単一の表面上の一致だけでなく、**効果の条件境界／丸めを区別できる比較ケース**を複数束ねる。実機試験を実施できないものは公開対象条件から外すか「未対応」としてUI表示する。`unsupported` がTOP50に存在しても他の正常セルを維持する。
