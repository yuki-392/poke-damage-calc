# U-01: 性格補正の製品仕様決定（確定）

- 決定日: 2026-10-23
- 判定: **A をユーザー承認済み**
- 対象: P0-03（UI倍率と実在性格の整合）
- ステータス: **製品方針確定 / 詳細契約に反映待ち**

## 決定内容

1. 入力UIは従来どおり、攻撃・防御等の関連能力に **0.9 / 1.0 / 1.1** の倍率を表示する。UI v0.5の画面構成を勝手に全面変更しない。
2. **計算に用いる各ポケモンの性格は必ず実在する単一の性格**とする。HP以外5能力への倍率の組がその性格の合法なベクトルと完全一致しなければ計算・保存・共有してはならない。
3. 型の正本は `natureId`。`natureFactors` は `natureId` と一致する導出値・通信時の検証用で、自由な独立入力値ではない。性格の正式な候補表（ID、表示名、五能力倍率）は、採用するゲームマスターの性格一覧と照合して確定する。HPの性格倍率は常に1.0。
4. UIで倍率変更を要求したとき、現在の性格が条件を満たすなら変更しない。そうでなければ該当倍率になる合法な性格候補を列挙する。**候補が複数ある場合は、他能力の倍率変化を示す候補選択UIを表示し、ユーザー選択前に変更を確定しない。** 候補が1つの場合でも他能力の倍率変化を見せる。キャンセルは元の性格を保持する。
5. 物理・特殊技が混在しても全5能力の性格補正を内部保持する。非表示の能力倍率も破棄しない。
6. ランキング元に性格IDがあるときはそのIDを尊重し、実測ではない推定データを実測と誤認させない。性格が不明なデータを、根拠なしに観測済みとして扱わない。
7. 保存／共有された合法性格と倍率ベクトルが一致しない、あるいは性格IDがマスターに存在しない場合は `invalid` として扱い、黙って補正しない。旧保存スキーマの移行は別途仕様化する。

## 例

- 現在の性格が「攻撃 1.1、特攻 0.9、その他 1.0」の場合、特攻を1.1に変更しようとすると、別の合法な性格へ切り替える必要がある。ユーザーが候補を選んだ後に一括更新する。
- すべて1.0の補正に対応する性格は複数ある。倍率だけから**元の性格名が一意には復元できない**ため、既存の `natureId` を優先する。

## 実装前に必要な検証・契約反映

- 性格マスター（25性格と重複する等倍性格）の出典／合法ベクトル照合（P0-04に連動）。
- `ValidatedPokemonBuild.natureId` および `natureFactors` の整合検査を、フロント入力確定・サーバ保存・共有受信・計算エンジン接続の各境界に明記。
- 入力未完成のドラフトと、保存可能な合法ビルドを区別する。`natureId: null` は**ドラフト/未完全データのみ**。保存可能な `ValidatedPokemonBuild` では不可。
- 異なる能力倍率への変更・性格の複数候補・キャンセル・保存復元・TOP50詳細の型編集についてテストを追加。

## Codex向け禁止事項

- 倍率を五能力それぞれ独立の自由入力とし、非合法ベクトルで計算すること。
- 表示倍率から一意に性格名が決まると仮定すること。
- 新しい候補が複数あるのに、ユーザーへ説明せず他能力の補正を自動変更すること。
- UI v0.5を新しい性格専用画面に勝手に変更すること。
