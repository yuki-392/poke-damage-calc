# U-02: 認証方式の製品仕様決定（確定）

- 決定日: 2026-10-23
- 判定: **B（Googleログイン＋メール認証リンク）をユーザー承認済み**
- ステータス: **製品方針確定 / UI・API・RLS・E2Eへの契約反映待ち**
- 関係資料: `champions-api-integration-design-v1.0/docs/auth-save-share-design-v1.0.md`、`champions-db-final-design-v1.2`、`champions-frontend-design-v1.0`、設計差分解消パック v1.1

## 製品仕様（決定事項）

1. **計算にログインを要求しない**。通常計算とTOP50計算の閲覧・編集はゲストでも使用できる。既存設計にある「ログイン不要で計算可能」を優先する。
2. 認証方式は **Supabase Auth による Google OAuth** と **メールアドレス宛のパスワード不要のワンタイム認証リンク（Magic Link）** の2方式を用意する。
3. 自前のパスワード入力・パスワードDB・パスワード再設定UIは作成しない。現段階ではメール6桁OTP入力UIも採用しない（リンク方式のみ）。
4. ユーザーIDの正本はSupabase Auth の `auth.users.id` とし、認証方法やメールアドレスをアプリ内データの主キーとして使用しない。
5. 既存の本人データの保存・一覧・編集・削除・端末間同期はログイン必須。共有URLの発行・公開閲覧権限はU-03以降で確定する（旧API設計の推奨案は未承認のため、ここで決定しない）。
6. GoogleログインとMagic Linkログインを別々に選べるUIを提供する。認証完了後は元の操作に戻せるようにするが、リダイレクト先はアプリ内の許可済み相対パスに制限する。
7. ゲストで編集していた未保存の計算条件を、認証に伴って勝手に破棄しない。自動的にサーバーへ保存もしない。復帰後の「保存」は明示的なユーザー操作とする。
8. 認証の成功・失敗・期限切れ・リンク使用済み・メール未着をそれぞれ適切に案内する。メールアドレスの存在有無を第三者に露出しない。

## 実装境界・セキュリティ要求（Codexへの設計指示）

- Next.js App Routerで Supabase のServer-Side Authを採用し、Cookieセッション＋PKCEに対応する。現時点の公式ガイドを実装着手時に再確認する。
- OAuthのコールバックとMagic Linkの確認処理は区別する。メールテンプレートはSSR／PKCEフローに合致した `token_hash` の受け渡しを設計する。生の認証トークンやセッションをアプリログ、URLアクセス解析、保存設定に記録しない。
- 本人確認はサーバーで検証したclaimsまたはAuthから検証済みユーザーを取得し、`getSession()`返却の未検証Userだけで認可しない。
- 保存した計算条件には `owner_id=auth.uid()` のRLSと最小限のSQL権限を適用。サーバー上で接続ユーザーごとのクライアントを扱い、管理者資格情報をユーザー保存処理に使わない。
- Redirect URLは許可リスト方式。任意の外部URLに転送しない。ログイン中のページや認証済みレスポンスは共有キャッシュしない。
- 認証リンクの送信レート制限・有効期限・配信制限、SMTP設定を公開前チェックに含める。Supabaseの既定値は契約仕様として固定しない。
- **同一メールアドレスのGoogleとMagic Linkが同一AuthユーザーIDになることを、確認なしに保証しない。** Supabaseのアイデンティティ連携仕様と実環境での挙動を検証し、意図しない別アカウント、勝手なアカウント統合、データ混在が起きないよう受入条件を定める。

## 画面仕様（UI v0.5を破壊しない追加）

- アカウント／ログイン導線に「Googleでログイン」「メールでログイン」を用意。
- メール入力→送信完了案内→メールのリンクから復帰。パスワード欄は不要。
- ゲストの計算画面に認証壁を置かない。保存時に限り、必要ならログイン画面へ誘導し、編集中の状態を失わない。
- メールの期限切れ・重複クリック・エラー時は再送可能な導線を表示する。ただし短時間の連続送信や乱用を抑止する。

## 受け入れテスト（設計案）

- AUT-01 ゲストで通常計算・TOP50計算ができる。
- AUT-02 Googleでログインし、本人の設定を保存・取得・更新・削除できる。
- AUT-03 Magic Linkを要求し、送信メールのリンクを1回使用してログインできる。
- AUT-04 Magic Linkの期限切れ・再使用・無効トークンでセッションが成立しない。
- AUT-05 別アカウントが他者の保存設定を取得・変更・削除できない。RLSとAPIの両方を検証する。
- AUT-06 ログイン後もゲスト編集状態が維持される。自動保存はされない。
- AUT-07 リダイレクト先に外部URLを指定してもオープンリダイレクトしない。
- AUT-08 OAuthとMagic Linkを同じメールで利用した場合の連携・非連携動作を実環境で検証し、データの所有者が変わらない。
- AUT-09 認証レスポンス・アクセスログ・計算設定に認証用tokenや秘密情報が残らない。
- AUT-10 メール送信レート制限・SMTPの本番運用が確認できる。
