# 04 — Champions用ダメージエンジン設計と検証

## 計算エンジン境界

`calculateDamage(request: DamageRequest): DamageResult`を唯一の算術処理口とする。入力は攻撃側/防御側の有効build、既知move、対戦形式、戦闘条件、固定されたrule/master/effect versions。通常モードもTOP50も同関数を呼ぶ。参照入力と版が同一なら同一の16ダメージ分布を返す。

結果を`ok` / `nonDamaging` / `missingContext` / `unsupported` / `invalid`へ判別可能に分類。未対応特性・持ち物・フォーム・威力変動条件を勝手に等倍扱いして`ok`にしない。移動技・固定ダメージ等の別演算経路を設ける。

## 能力・乱数・確定数

- UI v0.5で合意済みの暫定式：HP＝種族値＋能力ポイント＋75、その他＝floor((種族値＋能力ポイント＋20)×性格補正)、Lv50。採用対象フォームとゲーム内能力値の照合が必要。
- 能力ポイントは各0〜32、6能力合計66以内。ランク−6〜+6。性格は合法な単一ID→5能力倍率ベクトルの導出。**実機Stat Alignmentとの対応が未確定であることを保持**。
- ダメージは威力、攻撃、防御、基礎ダメージ、天候等、急所、STAB、タイプ、やけど、壁、ダブル範囲技、特性/道具の該当フェーズを別々に処理する。4096基準の固定小数と途中丸め順序は検証対象。**最終的に倍率を一括合成しない**。
- 現在の参照仮説は85〜100の16通りの乱数だが、丸めの境界とゲーム本体との一致を実機検証する。各出現値の重複は頻度として残す。
- n発撃破率は命中した技の乱数独立試行を仮定した確率分布の畳み込みで計算。n=1,2,3,...もサポート。命中率、ターン回復、状態変化、追加効果発生率を暗黙に混ぜない。多段/可変条件は別経路または未対応を返す。
- 表示例に合わせ、`56.25%→56.2%`は**小数第2位以下を切り捨てる表示案**として扱う。元のUIサンプルは切り捨てと整合するがユーザーの明示的丸めポリシー承認は未取得。内部確率は分数/十分な精度で保持し表示フォーマッタを独立させ、最終UI受け入れ時に確定可能にする。

## 特殊効果の設計

- 技/特性/持ち物の効果を`effectId`と発動条件、適用フェーズ、抑止条件、丸め、ゲーム検証証拠へ紐付ける。64項目の候補一覧は参考資料`references/effects-catalog-v1.2.md`。
- 差分抽出と分類：`verified` / `supported_unverified` / `audited_neutral` / `unsupported`（名称のある全収録効果が未分類0件となる）。
- ダブルの0.75補正は**複数の対象へ実際に命中した範囲技**の場合に限り、常時適用ではない。先制/場の状態/能力無効などの相互干渉や複数ヒットの処理は独立確認。
- 既知move以外/未登録持ち物の演算結果は信頼できないため、数値表示を停止するか`unsupported`として理由を表示。

## 自動比較と実機照合（P0-06）

1. L1：能力値、各段階の端数、4096、16乱数、KO確率の独立した境界テスト。
2. L2：`@smogon/calc`のChampions対応版（適切なライセンス/特定commit）等との同条件差分比較。**一致しても実機検証済みとはならない**。
3. L3：同一ゲーム版/フォーム/能力/条件の画面で実際のHP変動を採録し、再現可能なゴールデンケースに紐付け。1ダメージの不一致も「完全一致」ではない。
4. L3は通常/急所/壁/天候/ダブル/特殊な技/特性持ち物の**複合条件と丸め境界**を含む。ゲーム画面の証拠にない内部16段階の確率分布を検証済みと主張しない。
5. 50×4の統合テスト：1組の条件が通常モードと同じなら結果も同一。部分的な`unsupported`で他の対象行は継続表示。

参照試作`references/engine-prototype-v1.1.zip`はヒントに利用できるが、実機一致を証明するプロダクションコードではない。
