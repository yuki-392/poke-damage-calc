## 追加実装ルール

- 仕様ごとにテストを先行または同時作成する。4技すべてが`unsupported`でもUIはクラッシュしない。
- 旧SQL migration(`202610230001_...`,`202610230002_...`)は**参考**。初回はv1.2 DB設計をU-06で差分適用した**新baseline**を作る。
- 最初から全特殊技対応を保証できない場合は、実際の収録マスター全効果を分類し、未対応の理由を表示する。**支援範囲を明示し未対応の擬似計算をしない**。
- 商用/大規模運用サービス契約、APIキー、ユーザーのSupabase/Vercelプロジェクト作成はユーザーの明示操作が必要。勝手に公開/送信しない。
- DBやCronを本番へ適用する前に、planと破壊的変更の有無、rollback手順を提示する。
- スクリーンショットにある数値はダミー。ゴールデンテスト値と混同しない。
