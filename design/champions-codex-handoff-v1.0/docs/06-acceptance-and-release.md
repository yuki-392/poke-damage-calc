# 06 — 受け入れテストと本番公開ゲート

## 重要な区分

`design_ready`（本パック）、`implementation_ready`（実装・自動テスト完了）、`release_ready`（下記の実測・権利を含めた監査完了）は別。現在は**design_ready**。前2段階を満たしても公開承認とは限らない。

## 必須の自動テスト群

| ID | 検査 | 合格条件 |
|---|---|---|
| FE-01 | 通常4技・攻防交換・HPステッパー | 有効/無効ドラフトの切替、保存/再計算の境界が一致 |
| FE-02 | TOP50詳細を閉じる | 技・局所戦闘条件だけ破棄、型overrideだけ維持 |
| FE-03 | TOP50→通常転写 | 詳細変更後の技・局所条件・防御側型をコピー |
| FE-04 | シングル/ダブル切替 | 異なるsnapshotやoverrideを混在させない |
| FE-05 | PC/スマホTOP50 | 4技/固定タブ、HPバー・割合・確定数が視認可能 |
| API-01 | 未認証で計算 | 通常/TOP50は利用可、保存APIは認証要求 |
| API-02 | 個人保存セキュリティ | 他人のIDで漏洩・変更不可。RLSも実DBで検査 |
| API-03 | 保存DTO/不正Build | runtime schemaで拒否、schema versionとDB mode一致 |
| API-04 | 保存のrevision競合 | 古いrevisionなら409で上書きしない |
| SCOPE-01 | 共有機能削除 | UI/route/API/DBに共有機能が存在しない |
| RANK-01 | 同期ペア | singles/doubles各50、連番、重複なし・内部ID解決 |
| RANK-02 | 公開原子性 | 途中エラーで両形式とも旧版のまま |
| RANK-03 | 毎時更新 | 新版検知→30分待機、成功日は外部確認0、失敗時次回チェック |
| RANK-04 | 代表型 | 独立合成なら推定と表示、使用率不明はnull |
| ENG-01 | 演算 | 4096境界、16段階頻度、HP%、確定数、多段の不明状態 |
| ENG-02 | 未対応 | 不明な効果は`ok`禁止。`unsupported`理由が可視 |
| ENG-03 | 200組 | 1組が通常計算と同じ条件なら完全同値。部分失敗可 |
| AUTH-01 | Google/Magic Link | 未ログイン入力の維持、明示保存、ログイン/ログアウト時の漏洩なし |

## 手動検証・本番公開ブロッカー

- **P0-05**：ゲーム内Battle Data順位について、正式公開前にシングル50・ダブル50を同レギュレーションで確認し、フォームIDと順位全件一致。画面証拠/日時/シーズンを記録。以後は出典変化・異常の監査頻度を運用ポリシーとして明示。
- **P0-06**：採用ルールの整数ダメージ、相性/天候/壁/急所/特性/持ち物/ダブル等のL3実機証拠を保存。1ダメージの差も未解決扱い。動的威力・連続技の未対応は計算を止める。
- **P0-04**：マスターの収録/合法性のソース・ライセンス/帰属、Stat Alignmentと合法倍率ベクトルを照合。実際に採用したテキスト/画像の権利を確認。
- **OPS**：Cron・DBバックアップ・旧版保持/消去・失敗時旧データ表示、日付境界(JST)・外部レート制限・コスト・利用規約表示。
- **SEC**：実DB RLSテスト、CSRF/session/認証リンクリダイレクト、secret非露出、ログの個人情報とフィードデータ最小化。
- **UX**：375px前後のスマホ/PC、キーボード・スクリーンリーダー、モーダルフォーカス、ダメージ割合の可視化、色に依存しないHP表現。

リリース前に実機比較素材が得られない場合は**検証済みと偽らない**。ゲーム内ランキングの製品要件を満たさない状態を正式版として公開しない。開発用デモでは「参考データ/未検証」と明記する。
